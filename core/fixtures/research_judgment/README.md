# 研究判断开发集

这是公开的开发回归，不是封存题，也不是赛事获奖能力证明。

- `cases.json`：13道可见任务、原始材料与结构化答复合同。
- `rubrics.json`：开发金标，与可见材料分开；导出命令不会将它发给作答者。
- `core/test_research_cases.py`：从原始材料实际核算数值、可行性、秩与时间边界，检查金标完整性。它不是 Agent 的求解实现。

案例包括：同一矩阵的平均/最坏目标与未知订单比例；特征迟发与预处理泄漏；容量冲突与恢复可行、有限样本搜索；乘积参数族与独立补测；未知/已指定权重。案例数字是本项目自行构造的数据，不来自获奖论文。

答复中的 `quantities` 表示断言的点数值，未知量应省略，代表性参数组或条件函数放 `explanation`。`summary` 和 `figure_caption` 是结构化投影；评测器核对它们是否与答案一致，不理解自然语言摘要、图片或整篇论文。研究行动使用合同中的词汇，评分只核声明的类型，不能证明未来实验已执行。

2026-11-13 首次独立前向试用中，反演参数族答案被严格状态标签误拒。保留首轮12/13、原答案和原金标，经独立数学裁决后，仅为该案例允许 `insufficient_evidence` 与 `conditional` 两种状态；参数族范围、数值和禁止虚构单参数点值仍严格检查。后续使用须锁定金标哈希，不能隐去这次开发裁决。
