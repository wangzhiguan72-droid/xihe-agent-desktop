# 五条工作原则的落地核对

## 1. 一条主线到底

已落地。主会话通过 `model_spec`、`question_graph`、`contract_register`、`formula_register` 和 `stateBlock` 保存题目契约、变量、公式、路线、决定和数据版本；模型切换不会自动拼接互相矛盾的答案。多模型候选必须经过同口径比较或红队审查后才能被主线采纳。

## 2. 多模型用于挑错

已落地。`model_roles` 区分建模、编程、论文和审查职责；`subagent_run`、`deep_debate`、`redteam`、正式复算、`spreadsheet_diff` 和 `reconcile_artifact` 都把其他模型定位为复核或找错通道。TokenRhythm 判断层也遵守这个边界，不生成主解。

## 3. 人类经验规则化

已落地。数据少时避免无依据复杂模型、假设须有来源和必要性、公式先登记并做区分性测试、正式结果必须有运行证据、摘要和论文格式必须过门禁等规则已进入工具和交付审计。经验还可通过 `lesson_record`、`memory_write` 和知识库持续沉淀。

## 4. 自动执行，关键处停顿

已落地。`collab_mode=auto` 自动采用显式推荐，`collab_mode=collab` 在路线、方法和关键假设处暂停；审批工具、人类决策卡、自动续推和回退机制分别控制高风险副作用与普通流程。判断层的介入时机另由 `on_demand/smart/always` 策略控制，故它不是流程必经步骤；故障不会阻塞主流程。

## 5. 论文同时服务逻辑和评委

已落地。`abstract_check`、`paper_build`、`paper_contract`、`deep_visual`、`reconcile_artifact`、`support_pack` 分别检查摘要数字、篇章与页数、图表和排版、正文与结果一致性、支撑材料和 AI 使用详情。论文仍由主线模型统一写作，其他模型只做审查和修复建议。

## 判断层的持续校准

Jev 当前默认只做“主模型推荐一致性复核”：置信度低于 0.82、与主模型分歧、接口异常或缺少密钥时升级。`auto_override` 与 `allow_override` 默认关闭。后续可用人工最终选择与判断层记录构造校准集，再按任务类型调整阈值；在此之前不能把原始置信度当作准确率。

## 2026-10-21 边界审计：已落地不等于全部自动化

上面的“已落地”指主流程、工具和门禁已经具备对应能力，不表示每条原则都由引擎完全强制，也不表示已经完成长时间无人值守的竞赛验证。当前边界如下：

- **唯一主脑**是默认架构和证据归属规则，不是不可改变的模型锁。用户仍可切换会话模型或配置角色模型；`model_spec`、`question_graph`、正式运行和提交门禁负责把最终主线收回来。
- **经验规则**分为硬门禁和提示性规则。正式运行、输入版本、公式、复现、论文审计等有执行层检查；“数据少时不要上复杂模型”等经验目前要求模型给出依据并由人/审查模型核验，没有一个通用样本量公式替所有题目裁决。
- **异步能力**现已覆盖持久化后台队列、独立执行器认领、完成回执、本机持久通知和显式 `job_wait` 主线续接。安全重跑默认关闭，仅对脚本未变且显式允许的 Python 任务按上限重试；状态不明转人工核查。`dispatch_child` 仍要求同步总结，极致模式任务池重启仍按自身中断规则处理，不能把所有子代理与任意写任务都视为可自动重放。见 [异步调度说明](async-scheduler.md)。
- **多模型挑错**按深度档和任务需要启用；快速档不会自动派红队，多个审查者也不自动产生统计独立性。红队/辩论结果仍需主线模型接收并通过正式证据门禁。
- **Jev**是可关闭的有限选项复核器。`on_demand/smart/always` 只控制何时尝试调用；没有三候选卡、关键词未命中、低风险策略不适用或模型没有主动调用时，它不会介入。`0.82` 仍是运行门槛，不是已证实的校准准确率；`always` 只适合实验，不适合默认竞赛流程。
- **Modex**目前只吸收了检查点、组合技能和跨模型审查等设计思想，没有 Modex 运行时依赖或互操作接口。

因此，面向你自己的数学建模流程，核心是主线一致性、证据门禁、关键节点人工裁决、可选判断器、按需红队，以及可恢复的后台计算。每卡都判断、所有模型共同写作、六种模式全部暴露给新用户、任意程序断电后无条件重放和依赖 Modex，不作为默认承诺。
