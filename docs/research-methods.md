# 研究方法卡与判断评测

2026-11-13。此阶段将专家方法建议组织成可替换的研究 Skill，并把第一轮数值回归扩为研究判断开发集。不新增求解器依赖，不改变已有赛事规则、迭代采纳和视觉验收。

## 在项目中启用

打开左侧 **项目方案**，在 **研究方法** 选择 `xihe-research-methods`，按需要使用“补充”或“替换”，保存后创建数模会话。原有项目配置不会被自动覆盖。版本、来源、完整资源指纹仍由项目方案显示。

这是一个自包含 Skill，内有四张方法卡，Agent 按当前子问渐进读取：

| 方法卡 | 主要判断 | 失败后的行动 |
|---|---|---|
| 机理与反演 | 正向模型、量纲与守恒；观测是否能区分机制或参数 | 修正模型/实现，报告参数族或组合，设计能区分备选解释的新测量 |
| 预测 | 实际可得时间、朴素基线、训练内预处理与同窗口评价 | 作废泄漏比较，重建信息集、划分和拟合，再重算；不以单点优势外推 |
| 优化 | 目标、硬约束、可行域、求解状态及最优性证据 | 指出冲突或缺口；未授权不放宽约束；有限搜索只报已查集合的最好结果 |
| 多指标评价 | 指标方向、归一化、权重来源和排名翻转 | 给条件排名与边界，补偏好信息，披露敏感性，不靠事后调权制造赢家 |

每张卡回答适用情形、最小基线、升级信号、可执行检验及失败后的下一步。来源与适用边界写在卡末尾，均核对一手文献或官方文档。反演特别区分有限数据分不开、给定观测设计下理想输出恒等和组合被唯一识别，避免将局部秩诊断直接写成全局证明。

四卡、入口和 UI 元数据都在同一个技能目录，项目导出可带走全部资源。用户可以修改自己的方法 Skill，再在同一研究槽位切换，继续使用相同证据门禁与开发评测；本 Skill 不要求外部个人知识库或另一张已安装 Skill。

## 开发判断集

`core/fixtures/research_judgment` 含13个公开开发案例。题面和评分规则分开保存。目标变化、信息可得时间、硬约束、独立测量、权重等扰动，会改变正确的结论、范围或下一步行动。数值金标已用分数运算、完整枚举与秩计算独立核对。

结构化答复包含 `case_id`、`status`、`decision`、`claim_scope`、`quantities`、`next_actions`，以及适用时的摘要/图注投影。自由说明放 `explanation`，仍需人工审阅。只检查可比较的点值，允许指定的可选已知量；未知量或未经核验的额外点答案不能混入通过记录。

评分器会拒绝数值正确但范围过强、擅改约束、伪造缺失数据、沿用旧目标投影、重复/未知答案或自己填写 `passed` 的答复。缺答记为未验证，不当作通过。对状态词存在合理等价解释的案例，可显式配置允许状态集，同时保持数值、范围与行动检查。

评分器只检查**提交的结构化判断**，不认证推导、程序实际执行、数据来源或自然语言稿件。因此即使全部通过，报告也固定写 `execution_verified:false`、`blind_evaluation:false`，不能改称已跑完主模型或整题盲评。

## 命令

定向回归：

```powershell
npm run test:research
```

导出仅含可见材料的任务包，保留材料哈希与声明的模型/变体：

```powershell
node core/research_benchmark.js export --out <新的评测目录> --variant skill-only --model <实际模型标识>
```

该命令不会调用模型，也不会把金标复制到可见包。`variant` 和 `model` 是运行者的声明，不能据此证明模型或调用预算实际受控。应在隔离环境给作答者原始材料和选定 Skill，保存原始答复、真实执行记录和人工介入，之后评分：

```powershell
node core/research_benchmark.js grade --answers <answers.json> --out <report.json>
```

未提供答复、未全部通过或输入格式不合法时返回非零退出码。CLI 报告绑定题面、金标、答复文件的 SHA-256；导出目录已有不同内容时拒绝覆盖。不要把金标或评分反馈放回首次作答上下文。

## 已做的前向试用与限制

一次原生子代理在指定的隔离目录内使用本 Skill，未得到金标，完成13题并留下 PowerShell 计算脚本、原始输出和结构化答复。脚本在另一目录重放，答案与计算结果一致。初评分12/13；唯一不通过是参数族题的状态词，独立数学审阅确认其推导、范围和补测正确。保留原答复、原金标和初评分后，允许这项等价状态，复核为13/13，没有修改作答。

这是一次**开发前向试用及人工裁决**。目录读取边界是任务指令，不是经过认证的 OS 沙箱；所用底模不是由羲和生产调用链锁定，也没有同预算原版对照。试用时的技能快照保留，之后按独立审阅收紧了反演措辞；最终技能的加载、导出与四卡读取另经集成测试。因此不能用该分数声称 Skill 提升幅度、陌生整题迁移能力或获奖等级。

封存完整题、相同底模/材料/预算的原版—Skill—插件对照、实际正文与图件审阅仍属于后续阶段。开发题和前向输出均不得再被当成未见封存题。
