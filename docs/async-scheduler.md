# 可恢复的异步调度

## 使用入口

主界面工具栏的“后台任务”可随时打开任务面板。有排队、运行、失败、待核查任务或未读通知时，聊天区上方显示状态条。切换会话或项目后，列表、日志、操作和事件订阅按当前范围筛选。

面板显示任务状态、尝试次数、最近错误和输出日志；可以取消排队/运行任务、手动重试失败任务、标记通知已读。主流程因执行结果未知而暂停时，面板显示待核查原因及中断审批信息，用户检查已有产物后点“核对后继续”。该动作恢复原会话，后续工具仍遵守审批设置。

## 队列与执行器

`job_start` 先写 `data/jobs/<job_id>/meta.json`，再按 FIFO 派发，默认并发上限为 2。通用命令只允许 MATLAB `-batch` 与受 `pywrap.py` 守卫的 Python 脚本，不使用 shell 解释命令。Python 脚本在入队时记录内容指纹，派发和重试前再次检查。

原有 `kb_build` 使用固定内置 `kb_extract.py` 索引器，单独验证固定脚本、参数及输出目录，以 Python 隔离导入模式运行；它需要读取指定外部语料并写 `data/kb`，不会放宽通用模型脚本的守卫权限。

每次执行有独立令牌、心跳和完成回执。执行器独立于 HTTP 服务存活，直接写 stdout/stderr 日志。重启时认领有匹配执行身份的存活执行器，或读取匹配本次令牌的完成回执；确认成功后不再派发同一任务。取消请求交给匹配令牌的执行器处理，不按一个未经核验的 PID 直接杀进程。

| 状态 | 含义与下一步 |
| --- | --- |
| `queued` | 已持久化，等待可用并发槽位 |
| `starting` / `running` | 启动交接或后台计算中 |
| `succeeded` | 进程成功退出，结果仍需验证 |
| `failed` | 已确认失败；可按策略重试或人工处理 |
| `needs_review` | 无法确认执行结果、脚本改变或旧记录缺少身份；先核对产物 |
| `cancelled` | 已取消，不自动重新派发 |

同一数据目录由 `runtime.lock` 保证只有一个服务实例负责调度。显式换 HTTP 端口也不能绕过；隔离测试使用独立副本目录。删除仍有活跃后台任务的会话会被拒绝，先停止并等待取消完成后才能删除。

若 PID 仍存活但执行身份或心跳无法核实，任务转待核查并保留并发槽位，暂不允许重试或宣称已取消；后续出现有效回执或重新确认执行身份时继续更新，避免把未知执行当成空闲槽位重复派发。

## 原主线自动续接

主模型启动一个或多个任务后，可以调用 `job_wait({ids:[...]})`。系统保存原会话的等待记录、题目/数据版本和恢复检查点，结束本轮，避免反复轮询模型。只有等待的任务全部结束，才恢复同一主会话；不会另起第二主脑拼接答案。

等待期间遇到未回答的人类决策、审批或外部交接时，系统保持暂停。题目/数据版本改变、后台执行结果未知、恢复期间有未保存结果的工具调用时转人工核查。中断审批会保留摘要供核对，不静默重新批准或重放写入。

恢复调用失败且本次还未使用工具时，主流程最多尝试 3 次并退避；使用过工具后的异常交人工核查。用户手动继续或停止会取消旧等待，避免稍后恢复一条已经放弃的路线。后台日志只描述进程状态，不加入正式数值证据；模型规格、版本、复算与论文门禁继续独立生效。

## 失败续跑范围

默认 `retryable:false`、`max_attempts:1`。仅当调用者明确声明任务可以安全重跑、Python 脚本未改变且未超出次数上限（最多 5）时自动重新执行；这个声明也允许在执行器已消失、缺少完成回执时重新跑入口。未声明可安全重跑的模糊中断转待核查。MATLAB 输入与任意外部副作用无法可靠校验，保留人工重试；历史缺少可验证执行规格的任务不会直接重放。手动重试同样检查脚本指纹，改变后的代码需创建新任务。

续跑指重新执行任务入口，或者从已保存的会话历史继续请求模型。算法内部迭代位置、远端服务事务和任意进程内存并不由此恢复。`retryable` 是调用者对幂等性的明确声明，系统不能从脚本指纹证明所有输入、导入模块和外部写入都幂等。极致模式任务池与普通子代理仍按原有中断处理，不自动重放全部 agent 工作。

## 状态通知与接口

完成、失败、待核查与重启认领事件生成本机通知；记录和已读状态落在 `data/job_notifications.json`，服务重启和网页重连后仍可查询。通知通过 SSE 更新，轮询作回退；不会发送邮件或第三方消息。

- `GET /api/jobs?session_id=&project_id=`：任务、计数、待核查主流程和通知快照。
- `GET /api/jobs/detail?id=&session_id=&project_id=`：元数据及日志尾部。
- `GET /api/jobs/events?...`：首次快照及后续状态事件。
- `POST /api/jobs/retry`、`/api/jobs/cancel`：提交任务 ID 和当前范围。
- `POST /api/jobs/ack`：通知 ID 数组。
- `POST /api/session/resume`：会话 ID、项目范围与 `confirmed:true`。

带会话/项目范围的请求必须与任务归属一致；不带范围是本机用户的全局视图。API 继续使用应用现有的本机令牌校验。持久化环境仅保留执行所需的白名单字段，不保存模型密钥。`neohorse-1-9b` 判断层开关与本调度机制独立，关闭时流程照常运行。

## 验证

`npm run test:async` 包含队列、执行器、恢复、通知、独占锁及隔离 HTTP 集成测试；`npm test` 另覆盖既有功能和浏览器界面。集成测试用本机假模型服务和真实受守卫 Python，在临时副本中停止/重启服务器，验证后台计算只执行一次、原主线仅续接一次、通知已读跨重启、范围隔离与重复实例拒绝。
