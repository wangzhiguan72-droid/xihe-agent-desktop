# 工作模式与交付协议

> 三个入口共用本协议；平台差异由 `Codex适配.md`、`ZCode适配.md` 与 `DeepSeek适配.md` 决定。

## 1. 启动先锁定模式

每次新题或恢复项目时，先读取项目状态：

- `半自动模式`：关键选择由作者确认，智能体负责分析、实验、记录和执行。
- `自动模式`：作者明确授权后，智能体在授权范围内自行选择并连续推进，记录每个关键决定。

当前请求已明确“你决定/自主推进/自动完成”等授权时，直接记录为相应范围的自动模式，不再重复问。新整题在当前请求和项目状态均无模式/推进约定时，默认半自动＋逐问审核，首次仅全局审题后停，按[逐问推进与阶段授权](逐问推进与阶段授权.md)执行；无需仅为选模式再问。其他确实无法推断的关键范围简短澄清。局部审查、修复和排版按已授权范围执行，不为补字段重启全流程。
已有项目状态已记录模式时沿用，不因“继续”或沉默切换。模式切换必须由作者明确声明。

两种模式都不自动授权：上传、外发、提交、删除原始数据、修改宿主配置、修改全局模型/凭据、覆盖唯一可提交版本。

## 2. 半自动模式：关键节点给选择

普通读题、数据审计、公式核验、实验运行、排版修复和不改变主路线的复核，在当前获准工作单元内连续完成；不得据此越过该单元停止条件。逐问审核在全局审题、路线选择、模型规格、计算验证结果及小节/交接处暂停，具体范围见[逐问推进与阶段授权](逐问推进与阶段授权.md)；作者可明确合并单元。下列关键节点继续保留作者选择：

- 模型选择、求解方法选择；
- 关键假设或创新是否采纳；
- 主线叙事、重大结果解释和结论边界；
- 重大格式、交付版本或时间预算取舍。

模型与求解方法固定为 **4 个具体候选 + 1 个自定义 = 5 个入口**：只有一个具体候选标“（推荐）”。每项用通俗语言说明适配条件、证据、成本、风险、验证方式和预期产物。推荐不是已选；沉默、界面预选、超时或单说“继续”都不算授权。

其他关键节点按实际复杂度给 **3–6 个选项**；不足时不凑数，需要自由组合时保留“自定义”，不机械增加到 6 个。

## 3. 自动模式：连续推进但保留证据

作者明确选择自动模式后，智能体可以在七阶段内自行决定模型、求解方法、创新采纳、图量和论文组织取舍，并持续推进，不在每个节点重复询问。

每个关键决定必须记录：候选范围、最终选择、理由与证据、计算/写作成本、主要风险、被放弃的替代项、回滚点和待验证项。自动授权可以只覆盖当前问，也可以覆盖全项目；按授权的停止条件执行，不把“只自动跑问题一”扩大到后问。自动模式不是无审计模式，仍必须完成公式核验、最小基线、验证门禁、TeX Live 实编译、PDF 渲染和人工/独立审阅状态披露。

## 4. 主流程与独立门禁

七阶段仍是唯一主流程，是质量组织框架，不等于同时激活全部专项。全局先明确所有子问依赖，再在当前问内按需经过阶段2–6，各问接口完成后统一整合与阶段7终审；跨阶段/回退依证据执行，不机械禁止。

七阶段顺序：

`读题与范围 → 候选与形式化 → 数据与基线 → 主解与创新 → 验证与复核 → 写作与呈现 → 终审与交付`

借鉴数学建模总 skill 的门禁思想，但不照搬其固定图量和默认 Word：

- **M 建模门**：题目任务覆盖、假设来源与作用、量纲、初边值、可识别性和约束闭合；挂在“候选与形式化”之后。
- **P 最小运行门**：最小例、边界/约束、输出结构和合理量级；挂在“数据与基线”之后。
- **V 求解验证门**：按模型类型选择解析/守恒/网格/对照/敏感性或样本外检查；挂在“验证与复核”之后。
- **W 写作证据门**：逐问任务→方法→结果→检验闭环，图表、公式、引用、数字可追溯；挂在“写作与呈现”之后。
- **D 交付门**：当届规则、TeX Live 实编译 PDF、逐页渲染、Word/PDF 对账、复现说明和版本一致性；挂在“终审与交付”之后。

M/P/V/W/D 是横向质量层，不替换七阶段，也不制造额外的第八阶段。门禁状态使用 `PASS / FAIL / NOT_RUN / STALE / NOT_APPLICABLE`。模型、代码、参数、结果、图表、公式、规则或论文实质变化后，受影响门禁变为 `STALE` 并重审。没有真实独立审阅能力时标注“独立审阅未执行”，不得把主 Agent 自检写成独立通过。

## 5. 论文交付：LaTeX 主稿、TeX Live 编译 PDF 为最终件

- LaTeX 是唯一权威论文源码；默认使用当前环境实际可用的 TeX Live 编译链，优先 XeLaTeX/latexmk。
- 最终提交件是由 TeX Live 实际编译并逐页检查通过的 PDF。只有源码或未编译文件时，只能称为源码/阶段快照。
- Word 可以同时生成，作为阅读、协作和兼容性副本；不作为数学符号、公式分页和最终版式的权威源。
- Word 与 PDF 必须对账：题目、摘要、公式、数字、图表、引用、章节结构和结论一致；Word 的复杂公式或分页转换失败必须明确报告。
- 桌面上的 TeX Live 快捷方式只是环境线索；交付前仍需命令级探测和中文+公式+图表最小编译验证。
- PDF 需检查编译日志、未解析引用、字体、页面尺寸、空白页、裁切、图表 DPI、页码、匿名和当届官方格式。

## 6. 图量：证据优先 + 完稿后覆盖审计

过程阶段不按固定数量凑图。每张图先回答核心结论、独特证据、统计口径、版面尺寸和评审风险；无独特证据的图删除或留作内部备选。

全文写完且结果冻结后，再运行后置覆盖审计：按题目子问题核对原始数据图、过程/演化图、最终结果图、流程/路线图、验证/敏感性图是否缺项；将固定候选图数量作为覆盖诊断和补缺线索，不作为正文硬凑数门槛。

现有数学建模角色的“三类候选图 + 总体流程图”规则可以作为后置候选图集检查；国赛和 MCM/ICM 的当届官方规则、题目复杂度、篇幅和证据价值优先。最终入文图仍按论证需要选择，候选图和备选视角可以留在支撑材料。

## 7. 算法知识库、模板与统计工具

数学建模任务可先读当前环境提供的知识库入口，再按题型只加载相关方法卡和来源表；没有知识库时按题目与可核实理论选路。不得把知识库、历史模板或范文当成题目事实、官方规则或可直接提交的答案。模板/范文只借鉴结构、论证和版式，具体数值、代码和结论必须重新核算。

回归、统计推断和时间序列任务先确认当前可用的 Python 解释器及已安装的 `statsmodels`，运行时记录解释器路径、包版本、输入与脚本；其他 Python 解释器不自动视为同环境。若当前宿主真实暴露算法调度工具，可让它检索方法/模板或辅助调用，但工具可见性、包安装和推荐结果都不能替代题意分析、公式核验、实际运行和门禁。


具体发现、输入输出、MCP执行证据与失败回路见 [算法库与MCP调用](算法库与MCP调用.md)；阶段专长编排见 [技能组合与降级](技能组合与降级.md)。
