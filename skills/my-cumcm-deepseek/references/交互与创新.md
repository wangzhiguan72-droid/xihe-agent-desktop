# 交互、工作模式与创新决策

## 启动时先选工作模式

新题或恢复项目先读取 [工作模式与交付协议](工作模式与交付协议.md)，确认：

- **半自动模式**：关键选择给作者选项并等待确认；普通审计、实验、排版和不改变路线的工作可继续。
- **自动模式**：作者明确授权后，在七阶段内自行选择并推进；关键决定必须记录理由、证据、成本/风险、替代项和回滚点。

模式写入项目状态/工作记录；恢复时沿用已记录模式。`继续`、沉默、界面预选不切换模式，也不等于选择方案。两种模式均不自动授权上传、外发、提交、删除原始数据或修改宿主配置。

## 初次开场
先说明已知题目/阶段/已有产物、当前最关键未知项和当前工作模式。能从项目确定语言与格式就继承。不要一次问十几项配置。

## 决策卡
- 模型与求解方法：按题目证据给 **2–6 个有依据的具体候选**，只有一个具体候选标“（推荐）”；界面另加自定义与追问入口，只有一个候选时改用普通确认，不为凑数编造。
- 其他关键节点：通常列 **2–6 个选项**，不足不凑数，确有更多有意义候选时继续列；需要组合方案时保留“自定义”。
- 每项写清：适配条件、证据、假设代价、预期输出、计算/写作成本、风险、验证方式。
- 半自动等待作者确认；自动模式自行选但必须留下决策记录。
- 一个决策卡通常只处理一个核心问题；原生问答窗口可用时优先使用，否则完整展示文字菜单。

## 什么时候真要问
| 情境 | 半自动行为 | 自动行为 |
|---|---|---|
| 新题有多个可行模型 | 给 2–6 个有依据候选，等待选择 | 比较后选择并记录理由 |
| 求解器/算法改变结果口径 | 给 2–6 个有依据候选，等待选择 | 选择并记录替代项与风险 |
| 关键假设或复杂创新 | 给 3–6 项，等待是否采纳 | 做最小可证伪实验后自行采纳/撤回并记录 |
| 缺失边界有两种敏感解读 | 小规模比较后等待决定 | 比较后选定，保留未选解释 |
| 主线叙事或重大交付取舍 | 给 3–6 项，等待选择 | 选择并记录证据和回滚点 |
| 只改摘要/标题/排版 | 在授权范围直接改并核验 | 同样直接改并核验 |
| 截止临近 | 给收益/耗时/回滚选项 | 按已授权目标冻结稳定版并记录 |

## 创新评估协议
1. 把想法写成可检验主张：改变了哪个假设/约束/算法，预期改善什么指标。
2. 检查题目适配、数据可辨识性、物理/统计成立条件、算力与剩余时间。
3. 与最简有竞争力的基线比较，预先设指标、容差和停止条件。
4. 最小试验改变一个关键因素；多因素联动时做消融或明确只能解释净效应。
5. 结果分“支持/不支持/证据不足”；半自动交作者决定，自动模式记录是否保留、补试或撤回。
6. 新路线一旦采纳，列受影响方程、代码、结果、图、摘要及检验，失效旧证据并重跑。

创新可以来自解释、约束设计、可验证简化或验证方法，不以算法名词多为优点。若建议违背守恒、数据事实或统计有效性，指出反例；可保留探索分支，不能写成已验证正式结论。
