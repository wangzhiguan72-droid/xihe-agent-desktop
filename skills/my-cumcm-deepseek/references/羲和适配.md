# 羲和 Agent 适配

本入口 `my-cumcm-deepseek` 的羲和适配。羲和是**双模型角色分工 + 主/子智能体 + 技能槽位**的宿主；本文件把通用七阶段映射到羲和实际机制。模型名/端点以 `config/settings.json` 的 `role_models` 为准，**不硬编码模型名**（会改）；按角色名调用。三档 × 半自动/全自动的运行方式见 [羲和模式运行手册](羲和模式运行手册.md)，本文件只写机制映射。核对日期 2026-11-25。

## 1. 双模型角色分工

- `role_models` 四角色（settings.json:4-9）：**modeler/reviewer**（主脑/审查，当前 gpt-6-astra）+ **coder/writer**（编程/论文，当前 deepseek-flash）。路由/回退在 `core/model_roles.js` resolveRoleModel（显式会话选择不被静默回退）。
- 阶段映射：读题选路、候选与形式化、验证复核、终审 → modeler/reviewer；数据基线、主解代码 → coder；写作呈现 → writer。
- 第三裁判 `decision_judge`（settings enabled，当前 neohorse-1-9b）：**只收恰好 3 候选**做有限初筛；`shouldAutoJudge` 高风险词直接升级主模型/人；`swap_check` 反序双评防位置偏差；`auto_override:false` 不自动改推荐；不一致/低置信→escalate。
  → 结构化决策卡支持 **2–6 个有依据候选 + 界面自定义**；候选按题意列，不足不硬凑，只有一个真实候选时改用普通 `options` 或纯文字确认；超过 6 个先在 `deep_tree`/工作记录全量登记，再取最相关 6 个入卡，并在淘汰理由中交代其余，不静默丢方法。需要裁判初筛时，从卡内选恰好 3 个交 `decision_judge`（接口只收 3 个）；4–6 个候选的卡不自动进入裁判层，2 个候选的卡同样不自动裁判。高风险或裁判不一致/低置信→升级主脑或用户；半自动仍等用户确认，裁判不替代授权。

## 2. 主/子智能体（已实现，非占位）

- `subagent_run` / `dispatch_child`（core/agent.js runSubagent、tools.js）：独立调模型（resolveRoleModel）、真实工具执行但 `allowTools` 白名单强制、共享父工作区；worker 可读写，reviewer 与 crew 的 modeler/writer 为 `pyMode:'ro'` 只读，红队只许写 `findings/redteam/`；继承契约/公式/规格快照；**禁嵌套派活**（SUB_EXCLUDED）。动态池 `core/pool.js` 3 并发/12 硬上限（仅 extreme）。交接走 `core/handoff.js`（结构化、原文归档、文字报告≠证据）。
- **R1/R2 双盲终审**（见技能七条硬检查第4条）：两个 `subagent_run(profile:"reviewer")`。R1 在任务里限定只看论文与图，R2 限定只看代码、结果与日志；工具层只保证只读（`pyMode:'ro'`），不按路径白名单，范围靠任务说明与主代理复核；互不通气、不给对方结论，各自先立检查标准；主会话按实际文件与门禁核对冲突。fast 档无 `subagent_run`，标"双盲终审未执行"；`dispatch_child` 即使可用也只算辅助，不冒充双盲。
- 模式 `core/modes.js`：协作轴 `collab/auto` × 强度轴 `fast/deep/extreme` 共六种组合，未设置时按 `collab:fast`。**fast 隐藏 subagent_run 与 deep_debate/tree/loop/visual**；deep 解锁四种重手法；extreme 再解锁 CREW 三固定职责（modeler/coder/writer，各带职责提示词与工具白名单）、动态池（3 并发/12 上限）与 redteam。比赛中工具轮次上限 1500；全自动默认完全访问但 `dispatch_external` 被跳过。按当前档位编排，不承诺 fast 能派子代理。逐档操作、成本纪律与失败降级见 [羲和模式运行手册](羲和模式运行手册.md)。

## 3. 技能槽位（core/project_plan.js）

- `SLOTS=['research','figures','review']` + `main` 主槽；子槽默认 `mode:'off'`（空位待填），可 append/replace 主技能方法建议；`skill_load` 带 slot/mode 参数。冻结方案 main 槽优先于自动链。
- 本技能 `skill-contract.json` 声明 slots research/figures/review、modes append/replace：
  - **main**：本技能七阶段主控。
  - **research**：同类论文蒸馏与文献核验（[同类论文蒸馏与文献统计联动](同类论文蒸馏与文献统计联动.md)）。
  - **figures**：接 `plugins/evidence-figures` 绘图插件。按 [竞赛图表选型与视觉升级](竞赛图表选型与视觉升级.md) 选图，把要回答的问题、冻结结果路径、统计口径、面板尺度和导出尺寸交给绘图阶段，再按 [图表规范与出图时机](图表规范与出图时机.md) 验收。槽位关闭或插件不可用时，用本机绘图代码完成。
  - **review**：bzd-* 分章检查技能（共享技能根可发现）。

## 4. 对照实验与证据门禁工具

- `core/candidate_comparison.js`（由 iteration/deep_tree 调用，非独立工具）：排名只认 **formal 运行 stdout 的唯一 JSON 指标**，须声明 question/dataset/protocol/unit/direction 同口径，指标方向与定义冲突即拒。→ 双口径对照实验按此格式输出：事件口径=原始精度结果键，报告口径用于行文。
- 硬检查按现有门禁工具落实：机理检验→`conservation_check`（守恒/收支残差）+ `independent_verify`（双方法/独立重算）+ `repro_check`；公式→`formula_register`；规格→`model_spec`/`question_graph`；主张—证据→`claim_trace`；优化→`optimization_check`。`python_run` 守卫禁网/禁子进程，`formal:true` 才成证据。
- `core/blind_evaluation.js`（封存账本，非独立工具）：整题 original/skill/plugin 三臂封存账本（prepare/allocate/submit/review），**不运行模型**，评阅须 `reviewer_kind:'human'`，报告恒 `blind_evaluation:false`。→ 真实人工核验状态单独记录，不冒称自动盲评已开展。

## 5. 工具面与降级

- 约 60 工具（core/tools.js）：fs_*、shell_run（matlab -batch/pip/git）、python_run、job_start/job_status/job_wait/job_cancel、kb_search/kb_read/kb_build、skill_search/skill_load、memory_write/memory_recall/lesson_record、vision_read、web_search/web_fetch、academic_search、subagent_run/dispatch_child/dispatch_external、contract_register/formula_register/model_spec/conservation_check/repro_check/independent_verify/claim_trace/optimization_check、contest_rules/contest_clock/review_finding/verification_run、paper_build/support_pack/release_freeze 等。
- skill 加载：SKILL.md 全文进 system，references 列清单按需 `skill_load`（越界校验）。先读当前阶段所需参考，不一次全读。
- 能力探测优先：每轮先看宿主注入的协作模式与深度档位，再探测 `subagent_run`/`deep_*`/`crew`/`redteam` 是否实际可见；缺失→记录并降级串行最低流程，不模拟多代理、不改宿主配置/凭据/全局模型、不自行切档。

## 6. 与其他宿主的关系

同源七阶段/七条硬检查/双口径/证据纪律。羲和宿主按本文件的角色、槽位与门禁机制执行；不具备这些机制的宿主按自身实际工具落实同等检查，不伪造调用、不自行切档、不改宿主配置。
