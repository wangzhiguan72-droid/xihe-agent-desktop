# 原始精度与报告口径

关键结果保留计算值和展示值的可追溯映射，防止把舍入后的数值重新送入下游计算。这里的“事件口径”指本次计算保存的原始精度结果，不等于没有数值误差，也不自动证明物理/统计模型正确。它的可信程度仍取决于模型、输入、算法和验证。

## 两种口径

| 口径 | 记录内容 | 用途 |
|---|---|---|
| 事件口径 | 运行标识、结果键、原始精度值、单位、输入/代码/参数版本及来源 | 下游计算、约束与阈值判定、对照和敏感性计算 |
| 报告口径 | 从该结果按明确的单位换算、有效位数与舍入规则生成的展示值 | 摘要、正文、表图和结论 |

例如原始结果为 `205810.176088 s`，按最近整数舍入是 `205810 s`，换算并保留两位小数是 `57.17 h`。只有题意明确要求向上取整时才是 `205811 s`，应记录取整判据。以上仅为算术示例，不是任何新赛题结果。不存在适用于所有指标的“2026国赛统一舍入位数”；按题目要求、测量精度和数值误差确定。

## 关键结果如何留存

对会影响主要答案、极值、方案选择、排序、检验和敏感性结论的结果，保存同源映射。沿用项目的 JSON/CSV/XLSX/MAT 等可复核格式，不强制 Excel，也不要求全文每处数字后面括注长原值。

```json
{
  "result_id": "R-example",
  "run_id": "illustration-only",
  "key": "duration",
  "event_value": 205810.176088,
  "event_unit": "s",
  "report_value": "57.17",
  "report_unit": "h",
  "conversion": "event_value / 3600",
  "rounding": "nearest, 2 decimal places",
  "source": "results/run-id.json#duration"
}
```

实际台账还应关联输入/代码/参数哈希、日志和适用的误差或不确定性；不凭示例补造这些字段的值。排序、方案名称等非连续量记录原始判据、并列规则、可行性和选择依据，不人为给名称增加小数精度。

写作时引用报告值，关键表或支撑材料保留结果键和来源。图中可以使用不同的刻度精度，但需说明单位与精度，且能还原到同一运行。摘要不因台账格式变成长串原始数值；格式服从当届规则。

## 检查与失败回路

1. 从摘要/结论/关键表图抽查结果，找到对应运行与原始结果键，重新执行单位换算和展示规则。所有实际引用位置都应核对，不要求人为凑到“五处”。
2. 检查数据流：下游脚本读取原始精度字段；报告字段仅供输出。仅搜索变量名不能证明不存在回流，必要时追到读取、转换与计算语句或做边界例。
3. 比较排序、阈值和可行性时采用题目规定判据与经验证的数值精度。若误差足以改变判定，标证据不足并加密计算、报告区间或重新决策，不能靠更多小数制造确定性。
4. 事件值或输入/代码/参数更新后，旧的报告映射、图表与结论标 `STALE`，重算受影响链。检查附着在 V/W/D 等相应门禁，不另造 M4 等流程出口。

| 观察到的现象 | 可以判断什么 | 下一步 |
|---|---|---|
| 摘要 `57.17 h`，坐标刻度为整数小时 | 可能只是显示精度不同，不能直接判定回流 | 回查相同运行、单位与图数据，核对是否只是刻度格式 |
| ±10% 与 ±20% 扰动分别变化 0.8% 与 1.6% | 可能是合理线性响应，单看数值无法诊断错误 | 核对原始输出、基准、变化率定义及不确定性 |
| 下游确实把展示字符串转回数值计算 | 有数据流证据支持口径回流错误 | 改读原始字段，重跑受影响计算和论文数字 |
| 两个原始运行给不同答案 | 可能是版本、数据或参数不同 | 定位权威运行并保留差异，不通过统一文字掩盖 |

本规则与 [质量门禁与红线](质量门禁与红线.md)、[74小时基线与假设创新](74小时基线与假设创新.md)、[工作记录模板](工作记录模板.md) 配合；只有实际重新核验的结果才能宣称已通过。
