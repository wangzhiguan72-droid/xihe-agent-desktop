# 逐问推进与本轮执行范围

此参考把七阶段主流程落实到当前子问与工作单元，不另建一套总控。整题或跨问恢复时读取；局部润色只沿用当前范围，不重启读题。模式与质量门继续由[工作模式与交付协议](工作模式与交付协议.md)定义。

## 1. 总体规则与本次授权分开

“最终完成完整论文”说明项目目标；题面全读、LaTeX/PDF、证据门禁、资源入口是全局规则。它们不代表当前就授权求完所有问、加载全部专项或生成全文。先确定本轮对象、允许动作、所用版本、交付物和停止条件，只执行这一范围。先读主控、宿主适配、当前推进协议和项目状态，专项参考/技能到实际需要时再读。

新整题没有已有模式、推进约定或明确自主授权时，默认**半自动＋逐问审核**：首次仅全局审题，形成全部子问任务/约束/单位/附件字段/依赖和歧义后，停在全局审题审核，不进入正式求解或全文写作。无需仅为填写模式再问一次。恢复项目沿用已有约定；当前明确“自动完成全项目”“只做当前问直到……”等授权优先，不强制增加逐问停点。局部任务不改成整题流程。

用户单独说“优化这些Skill/提示词”，是在维护工具，不应借此读取、运行某道旧题。

## 2. 每轮有界工作单元

开始时用简短状态或现有记录说清：当前哪问/哪步、允许哪些操作、采用哪些已确认版本、输出什么、在哪里停。已有授权足够就直接执行，不重复征求许可。下表是默认逐问审核路径，可按实际已完成证据跳过，不为凑步骤重跑：

| 工作单元 | 允许推进的内容 | 本轮到达后停止 |
|---|---|---|
| 全局审题 | 全部题面/附件、任务契约、数据结构初查、各问依赖、歧义与计划 | 全局审题审核；不自动选定路线或运行主解 |
| 当前问路线 | 精简检索、原文/讲评、字典、文献及算法的相关片段；比较候选/基线 | 路线选择卡；模型/求解方法沿用2–6个有依据候选＋自定义、一个推荐 |
| 当前问模型规格 | 已选路线的变量/单位、假设来源、方程/目标约束、初边值、参数来源、输出接口和验证标准；公式自检/手工小例 | 模型规格审核；不自动进入正式数据的数值求解 |
| 当前问计算与验证 | 获准模型/代码范围内最小基线→主解→代码修复→必要诊断/反例/约束回代；保留日志/结果/诊断图 | 结果与验证审核；模型或关键假设需要实质改变则先回到相应选择 |
| 当前问小节与交接 | 获准采用且技术状态明确的结果写模型建立/求解、必要图表和局限；保存接口 | 小节/交接审核；不自动开始下一问主解 |
| 下一问 | 明确进入后先核继承接口是否足够，再进入该问路线/规格 | 当前授权的相应停点 |
| 全局整合 | 明确授权后统一各问主张/符号/版本，摘要、最终图表、编译、跨问检查与终审 | 全局结果/交付审核，或用户指定更早边界；不自动外发/提交 |

计算单元内部允许跨“基线—主解—验证”阶段连续修复，不每个函数/工具调用都停。诊断图可为审核生成，正式图仅用相应已核验结果；不必等所有子问结束才写小节草稿。用户可明确授权合并相邻单元或自动跑整问/全项目，主控记录范围并遵从。

全局审题已经明确理解全部任务，不等于提前敲定每问模型。路线不明时先保留候选，避免强行套一个全局算法。

## 3. 审核、运行授权与技术门禁不是一回事

- “采用方案2，先写规格书”：只授权按该路线写规格；不代表运行正式数据。
- “认可规格v1”：记录作者认可；若本轮未包含运行授权，仍停在规格审核，不默认为可运行。
- “规格v1通过，执行问题一计算与验证，到结果审核停止”：授权整个有界计算单元，普通修复/验证继续做；不能顺带跑问题二。
- “结果审核通过，写问题一小节和交接，到小节审核停止”：写作使用已核验结果；不能把人工认可替代失败的V门。
- “进入问题二，先看继承接口并比较路线”：可读后问及前问接口，尚未授权选定未决模型或解完整题。

“继续”不是万能授权：在已授权单元内继续执行；若上一轮仅展示**一个明确的下一动作**（例如“是否按规格v1执行问题一计算与验证，到结果审核停止”），用户回复“继续”可按该单步明确指向理解，落盘原意与范围，不再问同一句。若还有候选路线未选、多个不同下一步或其他实质歧义，“继续”不能替用户选路线、切换模式或无限推进；简短澄清，期间继续无依赖的已授权只读整理。不得把沉默、预选、超时当认可。

技术门禁状态PASS/FAIL/NOT_RUN/STALE/NOT_APPLICABLE、作者审核状态和可执行范围分开记录。用户认可不证明模型正确；技术PASS也不扩大当前授权。前问验证失败不能通过“作者已确认”包装为可用。

## 4. 全局看题，逐问执行，允许回退

“当前只解问题一”不禁止读取后问的题意、硬约束或共享参数；提前看依赖可避免前问漏存数据。不在未授权时创建/运行后问主解。数学上必须联合求解时，解释耦合原因、替代拆分与成本，半自动交作者决定，自动模式在授权内记录取舍。

每问交接至少保留：采用的题意解释和模型版本、公式/符号/单位、假设与适用条件、输入及代码/参数/结果版本和路径、事件/报告双口径、关键误差或不确定性、原约束回验、M/P/V/W状态、未决事项及下游依赖。按问命名可沿用项目规范，不要求固定result_1.json或01_Facts目录。结果JSON只是载体，不能只留下答案数值。

进入后问时加载全局任务契约和必要交接摘要，详细证据按路径回查；废弃探索与冗长日志留存、不默认全塞上下文。不要承诺真实清空会话、自动切换模型或永久清除错误影响。

若后问发现前问假设、单位、几何表示、参数或接口不适用，列影响链并将相关门禁/小节/下游结果标STALE，暂停依赖无效证据的计算。半自动时提出最小修订与重算范围等作者选择；自动模式在已授权范围修复。重验通过后才更新主版本和下游，保留此前版本并注明失效原因。经证实错误的基线不能仅为保底继续称可信。

## 5. 记忆与恢复

沿用项目现有context/workflow_memory.json或等价状态，按[工作记录模板](工作记录模板.md)补充可选execution_scope字段，不再并列创建Task_State.json。至少能恢复：当前问/单元、授权范围与用户原话摘要、输入版本、允许写入/运行的范围、输出路径、停止条件、waiting_for、已验证产物、跨问依赖、待决及活动作业。

开始下一轮先核当前授权和文件/版本，查旧进程避免重跑；到停点保存具体产物/检查证据和下一步。既有作者选择、授权和未变化的有效检查不重复索取。

这些是纯文本工作协议和状态记录，不是硬执行引擎；写JSON不会创造弹窗、自动调用API、定时唤醒或聊天清空。只使用当前宿主真实提供的问答/执行/后台/子代理能力；缺失时文字交互、串行分块或标明未执行。平台差异继续按对应适配处理。
