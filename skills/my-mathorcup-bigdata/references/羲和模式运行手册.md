# 羲和模式运行手册（妈妈杯大数据 · 三档 × 半自动/全自动）

> 适用 `my-mathorcup-bigdata` 的羲和副本。依据 `core/modes.js`、`core/agent.js`、`core/pool.js`、`contest_packages/mathorcup-bigdata/workflow.json`、`config/settings.json` 核对（2026-11-25）。宿主升级后重新核对；模型名、预算、并发数不写死。当届规则未核清时先做可验证的本地工作，不把往届条款当本届验收。

## 0. 每轮先读模式和赛事阶段

- 宿主每轮注入【当前协作模式】与【当前深度】；注入值优先于本技能的默认半自动，不因缺少文字约定切回半自动；缺失按 `collab:fast`。比赛会话另有【比赛时钟】和阶段规则（baseline/iterate/freeze/final），按当届实际截止推进，不套 74 小时或国赛比例。
- 术语对齐：本技能“半自动”=宿主 `collab`（你拍板）；“自动”=宿主 `auto`（引擎按推荐续推）。深度轴独立。
- 本技能不改档、不改 `settings.json`/凭据/全局模型。切档后已完成证据不重跑，受影响门禁标 STALE。
- 规则最先：`contest_rules` 登记已读取的届次、赛道、格式、AI 规定与来源；规则未登记不阻塞本地求解，但阻塞交付验收。

## 1. 六种组合的实际差异

| 组合 | 子代理 | 重手法 | 决策卡 | 写盘/执行审批 | 推进方式 |
|---|---|---|---|---|---|
| 人机协同·fast（默认） | 无 `subagent_run` | 无 `deep_*` | 按题意 2–6 候选+自定义，等你选 | 每次写/跑/派活前批准 | 一轮一步 |
| 全自动·fast | 无 | 无 | 按题意 2–6 候选+自定义，引擎自动选推荐 | 完全访问 | 自动续推至完成 |
| 深度协同 | reviewer/worker 可用（派活需批准） | 辩论/方案树/回改循环/视觉闭环 | 按题意 2–6 候选+自定义，等你选 | 批准 | 高成本精做 |
| 深度全自动 | 可用 | 同上 | 按题意 2–6 候选+自定义，自动选推荐 | 完全访问 | 无人值守高质量 |
| 极致协同 | 再加三固定职责、动态池、红队 | 继承 deep 全部 | 按题意 2–6 候选+自定义，等你选 | 批准 | 总师编排，人拍板 |
| 极致全自动 | 全部 | 全部 | 按题意 2–6 候选+自定义，自动选推荐 | 完全访问 | 无人值守全编制 |

- 比赛会话或全自动会话工具轮次上限 1500；普通人机协同非比赛会话 80；本地临时任务 18。宽上限不等于可以空转。
- `fast` 隐藏 `subagent_run` 与四种 `deep_*`；`extreme` 才允许 `crew` 与 `redteam`。
- 全自动默认完全访问（用户未把 approval 显式改为 ask 时），它只是不再逐次弹审批，不解除第 2 节的人不可代办项。

## 2. 所有档位共用的硬规则

- **规则与口径**：届次、赛道、初/复赛、题号、官方格式、AI 规定先从官方材料核实并登记；时标、单位、分母、区间定义不同先分列口径，再比较数值。数据下载、解码、时空有效性与入模资格分别验收。
- **证据口径**：只有 `formal:true` 运行、正式结果表与门禁记录算数值证据；子代理报告、辩论共识、红队结论、自然语言“已复算”都不算。权威顺序：确定性检查器 > 辩论 > 子代理报告 > 主模型判断。
- **门禁照跑**：`conservation_check`（或 not_applicable+替代检验）、`repro_check`、`independent_verify`、`claim_trace`、`optimization_check`、`paper_build` 不因 fast 或自动模式省略。
- **决策卡条数**：羲和 `ask_user` 结构化卡支持 **2–6 个有依据候选 + 界面自定义**；按题意列，不足不硬凑，只有一个真实候选时改用普通 `options` 或纯文字确认。超过 6 个有意义候选：先在 `deep_tree`/工作记录全量登记，再取最相关 6 个入卡，并在淘汰理由中交代其余，不静默丢方法。
- **第三裁判**：`decision_judge` 只收恰好 3 候选做低风险初筛；卡片正好 3 个时可自动进入，2 个或 4–6 个的卡保留主模型推荐、不自动裁判；需要初筛时也可从卡内选 3 个显式调用。`auto_override:false`；高风险、不一致或低置信升级主脑/用户。裁判不替代授权。
- **预算**：以 `settings.json` 的 `daily_budget` 为准（当前核对值 200）；每次重手法前一句话说明“为什么值得多花、预期拿回什么”；同一分歧只辩一次；预算熔断保留已完成部分。
- **不可自动代办**：提交、外发/上传、删除原始题面与数据、修改宿主配置/凭据/全局模型、代替队员确认 AI 披露与人工核验。自动模式也不授权。
- **失败如实**：下载失败、数据不可解、子代理超时、通道失败记“未完成/未执行”；失败的请求与轮次不算证据，主线可从首个未完成环节恢复。

## 3. fast 档：数据审计 + 逐问基线

目标是用最短路径把可解问题跑成真实基线，同时把不可解部分写成有边界的局部答案。

- **数据审计**：登记下载输入清单与哈希；检查格式可解、目标区域有有效值、时间支持与字段齐全；逐问登记可解性，一问缺数据不阻塞其他可解问题，也不把全题写成不可识别。
- **读题与路线**：`contract_register` 登记实体/边界/单位/目标/假设/规则；`question_graph` 建问题表。无 `deep_tree` 时用一页纸比较数据需求、特征/模型、实现代价、翻车点与验证方式；按题意给 2–6 个有依据候选，不足不硬凑，只有一个时普通确认。
- **求解**：先可信基线再改进；长作业 `job_start`→`job_wait`，不轮询；`formal:true` 才进证据链；同一结果换实现用 `spreadsheet_diff`/`result_compare` 互验。
- **验证**：守恒/收支、复现门禁、分母与时间对齐、训练/验证隔离、名义类码不当连续量；`independent_verify` 只核清单哈希与口径，不证明真实运行。自己另写实现可作替代复算，但披露同一人、共用数据与假设，不称独立。
- **图**：脚本出图后用 `vision_read` 自查轴、单位、图例、中文、裁切；没有 `deep_visual` 多轮闭环时，正式图宁可少而准。
- **终审**：R1/R2 双盲**未执行**（fast 无 `subagent_run`），如实标注；不要用 `dispatch_child` 冒充双盲。规则未登记时不伪造最终验收。
- **升档建议**：出现口径级分歧、优化反复不可行、独立复算与主解差距无法解释、图始终不合格或时间允许时，建议用户切 deep/extreme；不自行切档。

## 4. deep 档：四种重手法用在刀刃上

deep 继承 fast 全部规则；每用一种先说清成本理由。

- `deep_tree`：选路或卡住时用。`expand` 列 2–6 个思路不同的候选（数据路线、特征、模型、口径都算），先基线、再按证据缺口和预算增补对照；`select` 写选择与淘汰理由；`result` 只认 formal 运行 stdout 唯一 JSON 指标 + 同口径 `comparison`（question/dataset/protocol/unit/direction）与对应 `measurement_key`（须与 err.value 一致）。候选与理由进论文的模型选择说明。
- `deep_debate`：只用于会改主结论的分歧——口径、分母、时标、单位、样本外结论、关键数值没把握。3 个立场不同的只读 reviewer 独立取证，裁判归纳；产出分“已收敛/仍存疑”，存疑落局限；与门禁冲突以门禁为准；同一分歧只辩一次。
- `deep_loop`：优化类或约束可行性反复失败时用；求解器报错原文回灌，改公式或实现不静默；每轮进 `iteration`；迭代输出不构成数值证据，最终 formal 重跑 + `optimization_check` 回代。
- `deep_visual`：正式图逐图检查，FAIL 只改表现层不改数值；每张正式图一轮记录或写明跳过理由；视觉 PASS 不等于数学正确或 PDF 排版通过。
- 子代理：reviewer/worker 可用；半自动下每次派活需批准（除非已授权），全自动下不弹审批但仍受预算与边界约束；禁止嵌套；reviewer 只读，范围靠任务说明与主代理复核。
- **R1/R2 双盲**：R1 只看论文与图，R2 只看代码、结果、日志与复算清单；互不通气、不给对方结论，各自先立标准；主代理按文件与门禁核对冲突。R2 是审阅不是独立复算，复算须遵守不复用主解内核的隔离要求，两者分开记状态。
- 自动（auto:deep）：重手法同样先写成本理由；决策卡仍出，引擎自动选推荐；不为“自动”多开辩论。

## 5. extreme 档：三固定职责、动态池、红队

主代理是总师：编排、验收、汇总，不重复子代理的大段求解；子代理失败或容量不足时接管修复，只给最终文件与实际覆盖范围背书。

- **CREW**（仅 extreme，`subagent_run(profile:"worker", crew:...)`）：
  - `modeler` 只登记 `model_spec`/公式/假设/契约/问题表，不写代码；
  - `coder` 只按主代理给的规格写代码，不改公式；规格问题回报告；正式结果 `formal:true` + `model_spec_id` + `uses_formulas`；
  - `writer` 只写主代理标为 committed 的问题，每个数值有 formal 运行或结果表背书；不改公式、不改代码；
  - writer 与 modeler 的 Python 只读，coder 可写；工具白名单由执行层强制。
- **动态池**：只对独立问题、独立数据路线、高风险假设或专项核查开池；最多 3 并发、每局 12 个硬上限；连续两轮无新缺陷/新路径就收敛；预算紧张先收敛。
- **红队**：仅 extreme。优先攻数据泄漏（A3）、时点因果（t_avail≤t_dec）、量纲/口径（A4）、过度外推（A5）、图表正文一致（A6）、可复现（A7）；只写 `findings/redteam/`，探针落脚本并实际运行，退出码与 `report.json` 一致；红队结论不是主证据，主代理决定改结论、降主张还是补实验。
- **审阅层**：R1/R2 照做；可另派专项 reviewer 做复算分歧、论文规则与支撑包清单核对，但都只读、互不通气。
- **最小充分**：增加模型、特征、融合、代理或图表前，写明哪个题目要求或已证实缺陷尚未解决、基线为何不足、预期验证与预算；无可验证收益就保留简单方案，负面对照留档。

## 6. 半自动与全自动的操作差异

**半自动（collab）**

- 按题意给 2–6 个有依据候选的卡等你选；未选不推进该正式主线。只有一个真实候选时用普通确认；主线外的只读研究与低成本可逆实验可先做。
- `fs_write`/`fs_edit`/`python_run`/`shell_run`/`subagent_run`/`support_pack` 等每次弹审批；同类小写入批处理并一句话说明影响；不自行选择“本会话总是允许”。
- 派子代理前告知目的、权限和预期成本；R1/R2 冲突、红队证伪、复算分歧先报给你。
- 已授权单元做完直接进入下一步，不反复问“继续”；沉默、预选或超时不算授权。

**全自动（auto）**

- 关键选择仍要 `ask_user`：按题意给 2–6 个有依据候选，不足不硬凑，只有一个真实候选时用普通确认；引擎自动选推荐并继续；确实没有可列候选时，按自己的推荐决定并在契约/备注留痕，不空等；`recommendation_reason` 比较各候选对题目、数据、赛时的适合度，记录风险与回滚点。
- 执行层默认完全访问；`dispatch_external` 会被跳过，需要外部模型时留人工项；提交、外发、删原始数据仍然不做。
- 逐问 commit 后立即下一问；剩余时间或预算不足时，迭代卡推荐“停止迭代并冻结”。
- 完成时回复【全流程完成】+ 产物清单；规则登记、人工核验、AI 采纳与提交回执单列，不写成已完成。
- 自动不是免检：正式运行、独立复算、论文编译与逐页检查照旧。

## 7. 阶段 × 档位

- **baseline**：三档都先核规则与数据有效性，再逐问基线；deep 只在这里用一次 `deep_tree` 选路；extreme 先 modeler→coder 跑通第一问再开池，writer 只写已 committed 内容。
- **iterate**：fast 单线逐圈；deep 用辩论/回改循环处理真实分歧；extreme 可对独立问题开小池。所有档位先 `iteration({op:"plan"})` 预登记判据，结果出来不回头改判据；改上游输入/单位/时标/分母后重验下游。
- **freeze**：冻结输入、代码、结果清单；独立复算不读作者目标答案、不复用主解内核；deep 只做冲突裁决与正式图视觉检查；extreme 用红队攻关键主张；R1/R2 在冻结后终审。逐项区分舍入、实现、口径差异与真正矛盾。
- **final**：不引入新模型；重新编译并查看实际 PDF，核对正文计页/目录/完整源码/AI 披露与签署；`support_pack` 清单与体积按当届；生成包不等于已提交。
- 用户切档不重写历史证据，但受影响门禁标 STALE 重审；升档不把旧结论自动升级为“已验证”。

## 8. 失败与降级

| 情况 | 处理 |
|---|---|
| fast 无子代理 | 单主脑流程，双盲终审标未执行；`dispatch_child` 可用时也只作辅助 |
| 规则未核清 | 继续可验证的本地工作；交付验收标阻塞，不套往届条款 |
| 数据下载/解码/有效值失败 | 记录原始报错与已尝试方法；受影响问标缺口，其他问继续 |
| deep 工具不可用/超时 | 记录失败轮次，回退 fast 等价检查；失败轮不作证据 |
| 子代理未返回/掉线 | 主线接管必要修复；报告标“未返回”，不记通过 |
| reviewer 写入被拒 | 只读守卫的正常行为；改为读文件/只读 Python，落盘由主代理做 |
| 动态池额度/并发受限 | 收敛任务、串行关键路径；不伪造并发结果 |
| 全自动无人应答 | 按推荐推进并留痕；人不可代办项停在交付前，列待办 |
| 预算熔断/通道失败 | 停在首个未完成环节，保留证据，恢复后从该环节续跑 |

## 9. 开局自检与收尾

开局六问：① 当前 effort/collab？② `subagent_run`/`deep_*`/`crew`/`redteam` 实际可见吗？③ 本届规则、赛道与截止核清了吗？④ 本轮范围与既有授权？⑤ 时间与预算余量？⑥ 失败时降到哪条路径？

收尾报告：模式与档位；实际用了哪些能力（子代理/重手法/池/红队）；未执行项及原因（双盲、独立复算、人工核验、提交）；规则与证据路径；下一动作。不得把“档位开启”写成“检查已通过”，也不得把生成包写成已提交。
