# 用图组织证据

先写一句图要回答的问题，再选图。沿用项目的赛事、语言、页面及匿名要求；这份 Skill 只替换图表方法，不改变研究方法和验收。

## 选择表达方式

- **对象与模型**：真实对象 → 抽象变量/节点/边 → 模型机制 → 可核查输出。地图保留真实坐标、比例尺和底图来源；示意图明确不按实际比例。不要把概念箭头画成实测关系。
- **方案对照**：同一目标、数据、划分、单位和方向下比较基线与方案。前后图使用同尺度、同图例和相同区域；两张色图共用色标。两个不同目标的最优答案分面陈述，不称为性能提升。
- **机制解释**：区分数据图与示意图。路线、因果假设、变量关系使用可编辑图形；箭头含义写清。图中机制来自题设、公式、当前模型规格或已核查推导，不靠漂亮图形补出证据。
- **稳健性**：使用真实重算的参数点；标明固定条件、可行域和失败点。未计算区域不填补成观测，连线只是连接/插值；不凭单次运行画置信带。
- **全篇组织**：让图序从问题对象、方法到结果和边界递进。承担同一任务的图考虑合并；精确数值优先用表格，不要求每问一图。

具体选型和取舍见 [图表决策卡](references/figure-decisions.md)。参考来源及复用边界见 [来源说明](references/sources.md)。

## 可执行的小工具

[render_evidence.py](scripts/render_evidence.py) 从结果 JSON 的实际字段绘制分组柱图、成对前后点图、参数曲线，导出 PDF、PNG 和图件来源清单。不生成样本、不插补缺值、不自动证明收益。

先读 [配方格式](references/recipe.md)。项目启用 `evidence-figures` 插件时，先正常正式求解并 `link_run`，再用 `plugin_run` 传真实 `source_run_id`、结果 JSON 路径、配方路径和输出前缀。插件在输入副本上绘图，宿主记录 `plot_run_id`；主张的 `figures` 同时登记该编号与配方面板 ID。无需重写既有结果或假冒一次新求解。插件记录的程序版本与此 Skill 的方法版本分开查看。

未启用插件时，仍可用 `python_run` 在同一次正式运行中执行求解脚本和绘图脚本，声明 `result_files` 包含结果 JSON 与生成图件。脚本可从当前冻结 Skill 的只读目录加载，资源路径以实际 `skill_load` 返回的版本为准，不写死账户目录。更改图件后重新登记对应来源；不得用一张旧图冒充新运行产出。

数据图用 `claim_trace register` 绑定子问、实际字段、单位、展示值与面板。示意图先按 `kind=diagram` 挂接，再用 `register_diagram` 绑定题设/公式/规格；引用推导时附解析主张 ID。稿件和图版本稳定后再登记原句；更改题目目标、数据或图文后用 `claim_trace view` 查看失效项。

## 验收图件

检查最终排版宽度下字号、单位、图例、裁切、配色和标注；不要仅查看编辑器中的大图。用实际 `deep_visual` 逐图检查；读图失败应保留“未验证”。论文中的结论范围以研究证据为准，文件回执和图件清单只证明版本与来源，不证明像素、推理或因果成立。
